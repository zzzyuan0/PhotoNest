## Why

当前 `apps/web` 的页面虽然已经接上真实 API，但整体前端仍明显停留在“开发演示台”状态：首页、登录页和导入页充满技术说明式文案，用户很难快速理解下一步应该做什么；登录页强调会话机制而不是登录结果，导入页与图片查看页也缺少连续、直观的操作路径。结果是核心能力已经存在，但用户很难顺畅完成“登录 -> 导入 -> 查看 -> 继续操作”的主流程。

现在需要针对 Web 前端做一次面向真实使用场景的体验重构，把页面从调试导向改成任务导向，减少莫名其妙的设计文字，明确每个页面的单一目标，并让图片查看与后续操作具备更清晰的视觉层次和交互动线。

## What Changes

- 重构应用级导航、首页信息层级和页面文案，移除偏技术演示口吻的说明，改为面向照片管理任务的清晰引导。
- 重构登录页的信息架构与交互反馈，让用户能够理解“为什么登录、登录后会发生什么、下一步去哪”，而不是面对认证术语与会话字段。
- 重构导入页的上传流程展示，明确前置条件、上传进度、结果反馈与导入完成后的下一步操作。
- 重构首页中的图片浏览、详情查看和常用操作区，让“看图、切换、筛选、加入收藏/相册”等动作更顺手，减少跳跃式阅读与滚动打断。
- 统一前端视觉语言，包括页面标题、按钮命名、状态标签、空状态和错误提示，建立一致的轻量照片工作台体验。

## Capabilities

### New Capabilities

- `web-app-shell`: 定义 Web 顶层导航、页面入口层级、全局文案风格和首页任务分发体验。
- `web-auth-flow`: 定义登录页的表单结构、登录反馈、会话展示和登录后跳转引导。
- `web-photo-workflow`: 定义导入、浏览、查看详情和图片常用操作的一体化前端体验。

### Modified Capabilities

- 无

## Impact

- 主要影响 `apps/web/app.vue`、`apps/web/pages/index.vue`、`apps/web/pages/login.vue`、`apps/web/pages/import.vue` 以及相关前端状态与组件组织方式。
- 会影响 Web 端与 `/api/v1/auth/session`、`/api/v1/auth/login`、`/api/v1/import/*`、`/api/v1/discovery/*`、`/api/v1/assets/*`、`/api/v1/albums*` 等现有接口的呈现与调用时机，但不要求本次新增后端 API。
- 需要补充或调整前端测试，覆盖登录反馈、上传结果、图片查看切换与关键空状态/错误状态的表现。
