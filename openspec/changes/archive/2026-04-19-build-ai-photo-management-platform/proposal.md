## 背景

个人照片通常分散在手机相册、QQ 空间、聊天导出文件、云盘和电脑目录中，既难统一存储，也难按时间、地点和内容可靠检索，更缺少稳定的备份路径。现在多模态 AI、对象存储和异步处理基础设施已经足够成熟，适合把这些能力整合成一个可自建或云托管的统一照片平台。

## 变更内容

- 新建一个以照片资产为核心的管理平台，提供统一导入、对象存储落盘、派生资源生成和元数据索引能力。
- 增加可插拔的对象存储适配层，首版明确支持腾讯云 COS，并保留对其他 S3 兼容对象存储的扩展边界，避免领域模型绑定单一云厂商。
- 增加可插拔的 AI Provider 适配层，支持图像理解、OCR、向量化等能力，并将返回结果统一归一到内部元数据模型。
- 建立异步照片处理流水线，覆盖 EXIF 提取、地理反解、去重、描述生成、标签提取、OCR 和搜索索引更新。
- 提供面向用户的时间线浏览、地点浏览、自然语言搜索、重复照片审查和高价值相册整理能力。
- 提供二次备份和导出能力，确保主照片库始终存在独立的恢复路径。
- 增加访问控制、审计和隐私策略能力，确保原图、派生资源、导出包和敏感元数据默认私有访问，并降低密钥、预签名 URL 与调试数据泄露风险。

## 技术方向

- 前端采用 Vue 3 + Nuxt 构建首个 Web 客户端，承载上传、时间线、搜索、资产详情和设置页面。
- 后端采用 Go 模块化单体，并拆分为 HTTP API 与后台 Worker 两个运行角色，分别负责请求编排与异步处理。
- 前后端通过 OpenAPI 驱动的 HTTP 契约协作，而不是依赖共享语言类型；前端基于生成的 TypeScript Client 调用后端。
- 元数据与检索编排以 PostgreSQL 为事实来源，首版结合 `pgvector`、全文检索和 `pg_trgm` 支撑混合搜索。
- 异步任务采用 Redis 驱动队列，由 Go Worker 分阶段消费，覆盖派生资源、EXIF、AI 识别、索引更新和备份复制。
- 对象存储首版以腾讯云 COS 作为生产参考实现，开发环境通过 S3 兼容模拟器完成本地联调。
- 上传链路优先采用直传对象存储，API 负责导入会话、预签名信息、上传确认和后续入队。
- 本地 AI 能力作为独立扩展位接入，首版以统一 Provider 抽象为主，不要求 Go 直接承载主要模型运行时。
- 所有资产读取、导出下载和敏感操作都以应用层认证授权或短时签名为边界，不将原图、缩略图和导出工件作为稳定公网对象暴露。
- Provider 凭据通过受控配置源注入，日志、指标、任务载荷和调试输出不得记录完整密钥、预签名 URL 或敏感元数据全文。

## 能力范围

### 新增 Capabilities
- `provider-adapters`: 统一管理对象存储和 AI 服务的接入方式、配置校验、调用路由与降级策略。
- `access-control-and-audit`: 管理认证会话、授权边界、敏感操作审计以及浏览器侧请求保护。
- `photo-ingestion`: 导入照片和视频资产，完成去重、原图与派生资源持久化，并登记到主照片库。
- `photo-enrichment`: 异步提取 EXIF、地点、OCR、标签、描述和向量特征，并跟踪处理状态。
- `photo-discovery`: 支持按时间、地点、人物或主题与自然语言进行检索浏览，同时支持重复照片审查和精选相册整理。
- `backup-and-export`: 维护独立备份、完整性校验、可迁移导出包与恢复所需元数据。

### 修改 Existing Capabilities

- 无。

## 影响范围

- 需要新增 Nuxt Web 客户端、Go API、Go Worker 和 Redis 驱动的任务队列。
- 需要引入对象存储抽象、腾讯云 COS 配置与启动校验、AI Provider 抽象、元数据持久化、搜索索引能力、访问控制与审计能力，以及 OpenAPI 契约治理。
- 需要定义统一的资产模型、处理状态机、导入导出清单格式、隐私策略和跨前后端的分页与错误模型。
- 需要提供可直传对象存储的上传入口，以及承载时间线、搜索、归档和设置流程的 Web 界面。
- 需要增加密钥治理、默认私有读、导出受控访问、日志脱敏和敏感元数据最小暴露等安全约束。
