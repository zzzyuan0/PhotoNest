## ADDED Requirements

### Requirement: 用户可以把多个来源的资产导入同一个照片库
系统 MUST 支持将来自手机导出、桌面目录和历史导出包的照片与视频，通过直接上传或批量导入的方式汇总到同一个统一照片库中。

#### Scenario: 批量导入会创建照片库记录
- **WHEN** 用户或运维人员从受支持来源提交一次批量导入
- **THEN** 系统为每个被接受的条目创建资产记录，并把它们关联到选定的照片库或导入会话

### Requirement: Web 上传通过导入会话、预签名和确认流程闭合状态机
系统 MUST 在 Web 上传场景下由服务端创建导入会话、分配对象 key 并签发预签名信息，客户端直传腾讯云 COS 后，还必须调用确认接口完成入库闭环。

#### Scenario: 服务端为 Web 客户端签发上传凭据
- **WHEN** Web 客户端为某个待上传文件请求上传信息
- **THEN** 系统创建导入会话，分配与该会话绑定的对象 key，并返回仅适用于本次上传的预签名信息，而不是让客户端自行决定最终对象路径

#### Scenario: 上传完成后仍需确认才能入库
- **WHEN** 客户端声明对象已经上传完成
- **THEN** 系统在把资产标记为已接收前，先校验目标对象存在且与导入会话、对象 key 和预期元数据匹配

#### Scenario: 未确认或校验失败的对象不能被视为已入库
- **WHEN** 预签名已签发但客户端没有完成确认，或确认阶段发现对象不存在、大小不符或校验信息不匹配
- **THEN** 系统保持导入会话处于待确认或失败状态，且不会把该对象登记为正式资产

### Requirement: 上传凭据必须最小授权且对象标识不可猜
系统 MUST 为每次上传生成短时、单对象、单会话作用域的上传凭据，并使用不透明对象 key 保存源文件，不能把原始文件名、地点、相册名或用户输入直接编码进最终对象路径。

#### Scenario: Web 客户端请求新文件的上传凭据
- **WHEN** 用户为一个待上传文件发起新的导入请求
- **THEN** 系统返回的对象 key 为服务端生成的不透明标识，且上传凭据在有限时间内失效，不能被复用于其他对象或其他导入会话

#### Scenario: 过期上传凭据被重复使用
- **WHEN** 客户端尝试使用已经过期或会话不匹配的上传凭据继续写入对象存储
- **THEN** 系统拒绝把该写入视为有效导入，并要求重新创建导入会话或重新签发上传信息

### Requirement: 原始资产以不可变身份存储
系统 MUST 为每个被接受的资产分配统一资产标识，并在不修改原始字节内容的前提下，将原始文件持久化到主存储 Provider。

#### Scenario: 导入后原始文件保持不变
- **WHEN** 一张带有 EXIF 信息的图片被导入
- **THEN** 系统将其原始二进制内容作为不可变源对象保存，并在资产记录中引用它

### Requirement: 导入阶段必须识别重复资产
系统 MUST 通过内容哈希识别完全重复的资产，并通过感知相似度识别视觉上相近的候选资产，同时不能静默删除任何一条记录。

#### Scenario: 再次导入完全相同的文件
- **WHEN** 导入的文件与现有资产拥有相同的内容哈希
- **THEN** 系统把本次导入事件关联到已有资产，并将新提交标记为重复项，而不是再创建一个新的原始对象

### Requirement: 浏览流程所需的派生资源会被生成
系统 MUST 生成浏览流程所需的派生资源，包括缩略图和预览图，并将其与源资产及处理状态关联起来。

#### Scenario: 上传后成功生成缩略图
- **WHEN** 一张新照片被接收到照片库中
- **THEN** 系统至少生成一个缩略图或预览图，并在派生资源可用后将该资产标记为可浏览
