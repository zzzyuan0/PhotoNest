## Why

当前前端主页面、登录页和导入页里的大多数按钮已经绑定到真实函数与 API，但“点击后没有反应”的体感依然明显，因为不少动作缺少成功反馈、失败提示、处理中解释或后续跳转；与此同时，项目虽然已经具备上传、入库、异步增强、搜索和相册的基础骨架，却还没有把“上传照片 -> 识别 -> 分类 -> 在界面中可理解地看到结果”收成一个稳定、可验证的完整功能。

现在需要新增一个专门收口这条主链路的 change，把现有已实现能力、缺失环节和用户可见闭环统一梳理出来，避免继续停留在“局部接口存在，但端到端体验不确定”的状态。

## What Changes

- 梳理并收口 Web 端关键按钮的行为契约，明确登录页、导入页、照片库页中的按钮在可用、禁用、处理中、成功和失败时分别应该给出什么反馈。
- 补齐“上传成功后用户能看到什么”的端到端要求，确保新照片在确认入库后即使识别尚未完成，也能在列表、详情或状态区中被稳定看见。
- 明确异步识别增强链路的阶段要求，包括元数据提取、caption、OCR、embedding、索引更新，以及这些阶段如何映射成用户可理解的处理状态。
- 明确“分类”在当前项目中的落点：先以标签、地点、相册、收藏、搜索文档和检索状态作为当前版本的分类与整理结果，而不是默认假设已经有人脸、主题簇或自动智能相册。
- 为前端补充围绕当前选中资产的状态展示要求，让用户能区分“按钮未实现”“请求失败”“处理中”“结果已生成”这几种完全不同的情况。
- 为后端与 Worker 补充对完整链路的验收要求，覆盖上传确认、队列消费、识别状态推进、发现接口返回与前端呈现的一致性。

## Capabilities

### New Capabilities
- `web-photo-action-feedback`: 定义登录、导入与照片库页面中的关键按钮、空状态和操作反馈，确保用户点击后总能看到明确结果或原因。
- `photo-upload-recognition-classification`: 定义从上传确认到元数据提取、识别增强、检索整理与分类可见性的完整链路契约。

### Modified Capabilities

- 无

## Impact

- 主要影响 `apps/web/pages/index.vue`、`apps/web/pages/import.vue`、`apps/web/pages/login.vue`、`apps/web/lib/ui/workflow.ts` 以及前端状态提示与按钮可用性逻辑。
- 主要影响 `internal/ingestion`、`internal/enrichment`、`internal/discovery`、`internal/platform/httpserver`、`cmd/worker` 与对应的 HTTP/集成测试。
- 受影响 API 包括 `/api/v1/import/*`、`/api/v1/discovery/*`、`/api/v1/assets/*`、`/api/v1/albums*` 与登录会话相关接口，但重点是补足行为契约与可见性，而不一定要求大规模新增接口。
- 需要新增 OpenSpec specs 来约束“按钮反馈”和“上传到识别分类闭环”，并补充验证当前项目离完整功能仍有哪些剩余差距。
