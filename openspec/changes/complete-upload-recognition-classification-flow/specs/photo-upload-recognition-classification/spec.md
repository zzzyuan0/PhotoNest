## ADDED Requirements

### Requirement: 上传成功与识别分类完成必须区分为两个可见里程碑
系统 MUST 把“资产已确认入库并可见”与“识别分类结果已准备完成”区分为两个阶段，并在发现接口与前端展示中都保持一致。

#### Scenario: 资产已确认入库但识别尚未完成
- **WHEN** 用户上传照片并完成确认，后台增强任务尚未全部结束
- **THEN** 资产已经能出现在时间线或详情中，并以处理中状态说明识别分类仍在继续

#### Scenario: 资产识别分类完成
- **WHEN** 元数据、caption、OCR、embedding 与索引阶段已经达到当前版本定义的完成条件
- **THEN** 资产状态被更新为可搜索、可整理的完成态，并能在前端看到对应结果或摘要

### Requirement: 当前版本的分类结果必须以可落地字段对外可见
系统 MUST 将当前版本的“分类”落在结构化元数据、地点、caption、OCR、tags、搜索文档、收藏与相册等已有整理结果上，而不是依赖未实现的高级智能分类概念。

#### Scenario: 一张照片完成基础识别增强
- **WHEN** Worker 成功完成元数据提取、caption 或 OCR 中的已启用阶段
- **THEN** 资产记录保存对应的结构化结果，并可被 discovery 或资产详情接口用于摘要展示与检索

#### Scenario: 用户通过搜索或地点查看分类结果
- **WHEN** 用户使用搜索词、地点筛选、收藏或相册入口浏览照片
- **THEN** 系统能基于已有的 tags、caption、OCR、locationLabel、索引与相册关系返回相关结果

### Requirement: 前端必须能够判断后台识别分类是否真的在推进
系统 MUST 通过资产状态、摘要字段或其他稳定信号，让前端区分“刚入库”“识别中”“已可搜索”“部分失败”这些状态，而不是只暴露模糊的存在性结果。

#### Scenario: 后台任务顺利推进
- **WHEN** Worker 依次完成 metadata、caption、OCR、embedding 与 indexing 的已启用阶段
- **THEN** 前端可观察到资产状态从 `derivatives-ready` 逐步推进到 `metadata-ready`、`ai-ready` 或 `indexed`

#### Scenario: 某个识别阶段失败但资产仍存在
- **WHEN** 某个识别阶段失败而其他阶段仍已成功或可继续
- **THEN** 系统把资产保留在可见列表中，并明确标记为部分失败或需人工留意，而不是让它在界面中消失

### Requirement: 完整链路验收必须覆盖上传、Worker 与发现结果的一致性
系统 MUST 提供可回归验证的验收路径，证明一张照片能够从 Web 上传推进到后端识别分类，并在发现界面中以一致结果呈现。

#### Scenario: 端到端验收一张新上传照片
- **WHEN** 测试从 Web 导入一张新照片并等待后台任务推进
- **THEN** 能验证导入确认成功、资产状态推进、发现接口返回和前端展示结果彼此一致

#### Scenario: 当前实现尚未达到完整功能
- **WHEN** 某一环境中只能完成上传入库，但识别结果、分类结果或前端反馈仍有缺口
- **THEN** 验收结果必须明确指出缺失位于上传、Worker、接口还是前端呈现层，而不是笼统地报告“功能不可用”
