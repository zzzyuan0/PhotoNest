## ADDED Requirements

### Requirement: 关键 Web 按钮必须给出明确且可归因的交互反馈
系统 MUST 让登录、导入、刷新、搜索、收藏、加入相册、创建相册和导出等关键按钮在触发后给出明确反馈，使用户能判断动作是已开始、已成功、失败还是因前置条件不足而未执行。

#### Scenario: 用户点击已实现的动作按钮
- **WHEN** 用户点击一个已经接线到真实请求的按钮
- **THEN** 页面显示与该按钮对应的处理中、成功或失败反馈，而不是只有无变化的静态界面

#### Scenario: 按钮因前置条件不足而不可执行
- **WHEN** 用户尚未登录、缺少 libraryId、未选择文件或未选中当前相册
- **THEN** 页面明确说明按钮为何不可用，避免用户把禁用状态误解为功能未实现

### Requirement: 高风险或高频动作的反馈必须尽量靠近触发位置
系统 MUST 让收藏、加入相册、创建相册、导出和开始导入等动作的反馈尽量出现在按钮附近或当前操作区域，而不是只依赖全局顶部错误文案。

#### Scenario: 收藏或加入相册成功
- **WHEN** 用户在列表卡片或详情面板中点击收藏或加入当前相册
- **THEN** 当前卡片、详情区或相册区立即显示成功结果或已更新状态，用户无需猜测动作是否生效

#### Scenario: 创建相册或导出失败
- **WHEN** 用户在相册区或导出区触发请求失败
- **THEN** 失败信息出现在该区域附近，并指出失败与刚才触发的动作直接相关

### Requirement: 导入完成后的下一步必须明确连接到照片查看与识别结果
系统 MUST 在导入完成后告诉用户照片已经入库到什么阶段、接下来可以去哪里查看，以及识别整理仍可能继续在后台推进。

#### Scenario: 上传确认成功但识别仍在后台进行
- **WHEN** 用户完成一批文件的上传确认
- **THEN** 页面说明照片已进入照片库，同时明确提示识别、分类或检索准备仍可能继续进行

#### Scenario: 用户从导入页进入照片库
- **WHEN** 用户点击“前往照片库”或等价动作
- **THEN** 页面能够在照片库中看到本轮成功导入的资产，至少以处理中或已入库状态出现
