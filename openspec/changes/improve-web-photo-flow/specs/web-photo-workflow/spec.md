## ADDED Requirements

### Requirement: 导入页必须以步骤化方式呈现上传流程
系统 MUST 将照片导入体验组织为清晰的步骤流，至少覆盖准备条件、文件选择、上传进度和完成反馈四类信息，并让用户能够理解当前处于哪一步。

#### Scenario: 用户准备上传前查看前置条件
- **WHEN** 用户进入导入页但尚未开始上传
- **THEN** 页面会说明登录状态、目标 library 与选择文件等前置条件，并提供必要的引导操作

#### Scenario: 上传过程中查看整体进度
- **WHEN** 用户已经开始导入且队列中存在处理中项目
- **THEN** 页面会显示整体进度与单文件状态，并用可读文案解释当前步骤，而不是只显示技术状态值

#### Scenario: 上传完成后进入下一步
- **WHEN** 一个或多个文件成功完成上传确认
- **THEN** 页面会提示导入结果，并提供前往照片查看页或继续导入的明确动作

### Requirement: 图片浏览与详情查看必须保持同一操作上下文
系统 MUST 让用户在浏览照片列表时能够在当前页面上下文中查看选中图片的详情与操作，而不依赖长距离滚动才能找到详情区域。

#### Scenario: 用户在列表中切换多张图片
- **WHEN** 用户连续点击不同的照片条目或卡片
- **THEN** 详情区域会在当前浏览上下文中同步更新所选图片内容，而不会把用户强制滚动到远离列表的位置

#### Scenario: 小屏设备查看图片详情
- **WHEN** 用户在较窄视口中打开某张图片详情
- **THEN** 系统以抽屉、堆叠或其他适配形式展示详情，保证查看与返回列表都清晰可用

### Requirement: 图片预览状态必须清楚区分可看、处理中与异常
系统 MUST 为缩略图已就绪、处理中、处理失败或暂无预览资源的资产提供不同且可理解的预览表现，避免用户把处理中误认为上传失败或资源丢失。

#### Scenario: 缩略图尚未生成
- **WHEN** 资产已经入库但缩略图令牌仍未就绪
- **THEN** 列表与详情会显示统一占位和处理中说明，同时保留该资产的基本信息与可执行操作

#### Scenario: 资产处理异常
- **WHEN** 资产处于部分失败或预览异常状态
- **THEN** 系统明确告知该资产已存在但当前预览受限，并提示用户可执行的后续动作或重试路径

### Requirement: 常用图片操作必须围绕当前选中资产集中呈现
系统 MUST 将查看详情、加入收藏、加入相册等高频动作围绕当前选中资产集中展示，避免用户在多个分散区域之间来回寻找操作入口。

#### Scenario: 用户查看某张图片后执行整理动作
- **WHEN** 用户打开一张图片详情并准备收藏或加入相册
- **THEN** 相关操作会直接出现在当前图片的预览或详情区域附近，而不是要求用户回到远处的列表或其他面板
