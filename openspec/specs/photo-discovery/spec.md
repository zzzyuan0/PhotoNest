## Requirements
### Requirement: 新上传资产在增强处理中也必须可被浏览和查看
系统 MUST 让已确认入库的资产在增强任务尚未全部完成时，仍然出现在总览、时间线和资产详情接口中，并明确返回处理中状态。

#### Scenario: 新上传图片尚未完成全部增强
- **WHEN** 用户上传一张图片、确认成功，但 Worker 仍在处理缩略图或识别任务
- **THEN** 总览、时间线和资产详情接口仍返回该资产，并标记其增强状态为处理中

### Requirement: 发现接口必须基于持久化资产事实返回查看句柄
系统 MUST 基于 PostgreSQL 中的资产与对象引用记录生成列表摘要、详情内容和受控查看句柄，而不是依赖 API 进程内存中的临时状态。

#### Scenario: 服务重启后查看最近上传的图片
- **WHEN** 用户在服务重启后打开最近上传图片的时间线卡片或详情页
- **THEN** 系统仍能根据持久化记录返回该资产的摘要信息、处理状态以及受控的预览或下载访问方式

### Requirement: 用户可以按时间和地点浏览资产
系统 MUST 提供按拍摄日期、导入日期和已解析地点元数据分组与过滤的照片库视图。

#### Scenario: 时间线视图按拍摄时间分组照片
- **WHEN** 用户打开时间线视图
- **THEN** 系统基于最佳可用拍摄时间按时间顺序展示资产，并支持按日期过滤

### Requirement: 用户可以执行混合照片搜索
系统 MUST 支持将结构化过滤、全文元数据、OCR 文本和 embedding 语义匹配整合到同一个查询流程中的混合搜索。

#### Scenario: 自然语言搜索返回相关资产
- **WHEN** 用户搜索“去年夏天和家人在海边拍的照片”
- **THEN** 系统综合时间信号、caption 或 tag 命中以及语义相似度，对相关资产进行排序并返回结果

### Requirement: 发现流程要暴露重复项和精选集合
系统 MUST 提供重复照片审查、收藏以及运维人员或用户自定义的高价值相册视图，从而让用户不需要为每张照片手工建文件夹也能维持主库整洁。

#### Scenario: 重复照片审查显示候选对
- **WHEN** 照片库中存在视觉相似度超过配置阈值的资产
- **THEN** 系统在重复照片审查视图中展示这些候选项，并在用户明确操作前不删除任何资产

### Requirement: 搜索和浏览结果必须反映识别状态
系统 MUST 在发现流程中暴露足够的处理状态信息，以便用户区分已经完成索引的资产和仍在等待识别增强的资产。

#### Scenario: 新上传资产仍在建立索引
- **WHEN** 用户打开一个已经完成上传但尚未完成语义索引的资产
- **THEN** 界面仍然在照片库中展示该资产，并显示其识别增强仍在处理中，而不是把它从所有发现视图中隐藏

### Requirement: 发现接口必须执行授权并最小化敏感字段返回
系统 MUST 只向已授权会话返回照片库资产，并且在列表、搜索和详情接口中遵守最小字段原则，不默认暴露稳定对象 URL、内部对象引用、原始 GPS 坐标或完整 OCR 文本等高敏感字段。

#### Scenario: 未认证客户端请求搜索结果
- **WHEN** 未认证或无权限的客户端访问时间线、地点浏览或自然语言搜索接口
- **THEN** 系统拒绝返回资产列表、缩略图访问句柄和敏感元数据

#### Scenario: 已授权用户浏览时间线列表
- **WHEN** 一个已授权用户请求时间线中的资产摘要
- **THEN** 系统返回当前列表视图必需的展示字段和受控缩略图访问方式，而不是稳定公网 URL 或可直接复用的内部对象标识
