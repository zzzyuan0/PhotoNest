## Requirements
### Requirement: 登录页必须让用户理解登录目的与结果
系统 MUST 在登录页中清楚说明为什么需要登录、用户需要输入什么、登录成功后可以访问什么内容，并在登录成功后展示可理解的身份摘要。

#### Scenario: 首次进入登录页
- **WHEN** 用户第一次打开登录页
- **THEN** 页面会用简洁文案说明登录用于访问照片库与导入能力，并突出用户名、密码和主登录动作

#### Scenario: 登录成功后展示身份摘要
- **WHEN** 用户提交正确凭据并成功创建会话
- **THEN** 页面显示当前登录身份、可访问的 library 范围和下一步动作入口，而不是只停留在技术返回内容

### Requirement: 登录反馈必须明确区分处理中、失败和成功
系统 MUST 为登录操作提供明确的按钮状态、错误提示和成功反馈，让用户能够判断当前请求是否仍在处理中、是否失败以及是否可以继续下一步。

#### Scenario: 登录请求处理中
- **WHEN** 用户提交登录表单且请求尚未完成
- **THEN** 登录按钮显示处理中状态且不可重复提交

#### Scenario: 登录失败
- **WHEN** 用户提交的凭据无效或接口返回错误
- **THEN** 页面在表单附近显示可理解的失败原因，并保留用户继续修正输入的路径

### Requirement: 登录成功后必须提供明确的后续导航
系统 MUST 在登录成功或读取到当前会话后，提供进入首页或导入页的明确动作，避免用户停留在只读会话页面中不知道下一步该做什么。

#### Scenario: 已有会话的用户回到登录页
- **WHEN** 用户访问登录页且系统已检测到有效会话
- **THEN** 页面会提示当前已登录，并提供进入照片库或继续导入照片的显式入口
